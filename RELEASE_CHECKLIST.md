# Oblivion Android — Release Checklist

## Before distributing a test build

- [ ] GitHub Actions completes `:app:testDebugUnitTest`, `:app:assembleDebug`, and `:app:assembleRelease` successfully.
- [ ] `scripts/verify_oblivion_source.py` passes.
- [ ] `scripts/test_verify_apk.py` passes.
- [ ] Both APKs pass `scripts/verify_apk.py` for application ID, ARM64-only ABI, and 16 KB native load alignment.
- [ ] SHA-256 checksum matches the downloaded artifact.
- [ ] The debug APK is installed and tested on a physical device using `DEVICE_TEST_MATRIX.md`.
- [ ] No Microsoft/Xbox tokens, device codes, private account identifiers, keystores, or local SDK configuration are included in logs or archives.

## Before a production release

- [ ] Complete all required device acceptance tests and record the Minecraft version/device matrix.
- [ ] Review the upstream and third-party license/notice obligations before redistributing binaries.
- [ ] Create and protect a release signing key outside the source repository.
- [ ] Configure signing through GitHub Actions encrypted secrets or another protected signing environment; never commit a keystore or password.
- [ ] Produce a signed release APK and verify its package ID, signature, ABI, native alignment, and checksum.
- [ ] Test upgrade/install behavior from the prior signed release using the same signing identity.
- [ ] Publish a changelog, minimum requirements, known compatibility limits, and rollback instructions.

The release artifact currently generated by CI is `app-release-unsigned.apk`. It is not a production-signed release and must not be described as one.
